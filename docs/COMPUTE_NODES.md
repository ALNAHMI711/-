# عقد عُقد التشغيل السحابي

## الهدف

الهاتف هو واجهة التحكم فقط. الأعمال الثقيلة تستمر على Worker سحابي أو خادم خاص حتى بعد إغلاق المتصفح.

## أنواع العمال

- `free_tier`: موارد مجانية متاحة عند وجودها، مع مراقبة الحصص والحدود. لا يفترض النظام أن المجانية دائمة.
- `private`: خادم يملكه المستخدم ويمكنه تنفيذ الأعمال الثقيلة والاحتفاظ بها كخيار أساسي أو احتياطي.

## الأمان

- لا تُحفظ كلمات مرور الخوادم أو مفاتيح SSH داخل نموذج العقدة.
- تستخدم العقدة الخاصة مرجع اعتماد opaque مثل `credential_ref`، بينما تحفظ السرية في مخزن أسرار منفصل.
- يفضّل أن يبدأ العامل الخاص اتصالاً صادرًا آمنًا إلى طبقة التحكم بدل فتح منافذ إدارية خطرة للعامة.
- لوحة الهاتف لا تصل مباشرة إلى Docker/SSH؛ تمر الأوامر عبر طبقة التحكم المصرح بها مع سجل تدقيق.

## التوجيه

1. لا يُرسل Job إلا إلى عقدة `ONLINE` ذات سعة متاحة.
2. يجب أن تطابق قدرات العقدة متطلبات Job.
3. يفضّل النظام العقدة الأقل تحميلًا.
4. إذا فشل عامل، تُستبعد العقدة ويُبحث عن مرشح Failover آخر.
5. انتهاء حصة Worker مجاني يجعله غير متاحًا للأعمال الجديدة حتى تتجدد الحصة أو يتوفر Worker آخر.

## حالات العقدة

`ONLINE`، `OFFLINE`، `DRAINING`، `ERROR`، `UNKNOWN`.

`DRAINING` يعني عدم استقبال أعمال جديدة مع السماح بإكمال الأعمال الحالية.
