# ربط الحسابات والقنوات والتحقق

هذه المرحلة تضيف الأساس الآمن لمركز **الحسابات والقنوات** في مشاهد.

## المسار

1. يختار المستخدم المنصة والمشروع.
2. يضغط **ربط الحساب**.
3. ينتقل إلى OAuth الرسمي للمنصة.
4. يمنح الصلاحيات بنفسه.
5. يعود إلى مشاهد، ثم يفحص النظام الاتصال والصلاحيات.
6. لا تُخزن كلمات مرور المنصات، ولا تُكتب رموز OAuth الخام في السجلات.
7. لا يُسمح بالنشر إلا بعد نجاح فحص الاتصال والصلاحيات المطلوبة.

## حالات الحساب

- `disconnected` — غير مربوط.
- `pending` — ينتظر إكمال OAuth.
- `connected` — متصل.
- `expired` — الصلاحية منتهية وتحتاج إعادة تفويض.
- `error` — حدث خطأ يحتاج معالجة.

## التحقق

التحقق الآلي يعتمد على المعلومات التي توفرها المنصة رسميًا. إذا كانت صلاحية مطلوبة ناقصة، يظهر للمستخدم الإجراء المطلوب بدل تجاوز المنصة.

## تحقيق الأرباح

مشاهد يميز بين **الجاهزية** و**التفعيل الفعلي**. لا يدّعي النظام أن القناة تحقق أرباحًا دون حالة رسمية من المنصة.

إذا كان للمنصة API رسمي يوفر حالة تحقيق الأرباح، يحولها الموصل إلى حالة موحدة. وإذا لم تتوفر، يعرض النظام: **يجب إكمال هذا الإجراء من الصفحة الرسمية للمنصة** مع إرشادات المستخدم.

الحالات الموحدة:

- `unknown` — لا توجد معلومة رسمية قابلة للتحقق آليًا.
- `eligible` — مؤهل وفق البيانات الرسمية المتاحة.
- `enabled` — مفعّل وفق البيانات الرسمية المتاحة.
- `action_required` — توجد خطوة على المستخدم إكمالها.
- `not_eligible` — غير مؤهل وفق البيانات الرسمية المتاحة.
- `not_supported` — لا يدعم الموصل هذا الفحص رسميًا.

> هذه الطبقة لا تتحايل على التوثيق، ولا تتجاوز المراجعة، ولا تضمن قبول تحقيق الأرباح.

## الخطوة التالية

إضافة موصلات OAuth الفعلية لكل منصة، مع تخزين آمن للرموز، وتجديدها، وفحص الصلاحيات، وصفحة واجهة عربية تعرض حالة كل قناة/صفحة وإجراءاتها.
